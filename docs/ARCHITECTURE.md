# Архітектура Vade Launcher

## Компоненти

```
            Головний ПК (адмін)                                    Ігрові ПК (×29+)
 ┌──────────────────────────────────────┐            ┌──────────────────────────────────────┐
 │ Vade Launcher (Electron)             │            │ служба VadeAgent (LocalSystem)       │
 │  renderer: React UI                  │  WebSocket │  VadeAgentService.exe (WinSW)        │
 │  main:  AgentHub ── AgentLink ×N ────┼───────────►│   └ VadeAgent.exe (Node SEA)         │
 │         WolScheduler ── UDP magic ───┼──► 10.70.4.255:9   ├ WS-сервер :7420 + автентифікація │
 │         AdminStore (settings/pcs.json)│            │   ├ JobRunner (порт .bat)            │
 │         Scanner (ping+ARP)           │            │   ├ AgentScheduler + RTC-таймер      │
 │         SitePublisher ── HTTPS POST ─┼──► сайт    │   ├ OccupancyDetector (кожні 10 с)   │
 └──────────────────────────────────────┘  клубу     │   └ C:\ProgramData\VadeAgent\        │
                                                     │ сесія гравця: репортер (Users-задача)│
                                                     │   GetLastInputInfo, вікно, процеси ──┼─► presence\session-N.json
                                                     └──────────────────────────────────────┘
```

Монорепозиторій (npm workspaces):

| Пакет | Що всередині |
|---|---|
| `packages/protocol` | типи протоколу та налаштувань, дефолти, seed-список ПК, формула розкладу, валідація, HMAC/AES (тільки Node) |
| `apps/agent` | агент: `src/jobs` (кроки обслуговування), `src/steam` (VDF, бібліотеки, SteamCMD), `src/win` (реєстр, junction, живлення, RTC), `install/` (інсталятор служби) |
| `apps/admin` | `src/main` (Electron: сховище, WoL, з'єднання з агентами, планувальник, сканер), `src/preload`, `src/renderer` (React UI) |

## Чому такий стек

Специфікація дозволяла Tauri/Rust, Electron або C# WPF — «найстабільніший варіант для LAN Windows».
Обрано **TypeScript скрізь**:

* **Один спільний пакет протоколу.** Адмінка й агент компілюються з тих самих типів, тож розбіжність формату повідомлень ловить компілятор, а не клуб о 3 ночі.
* **Без нативної компіляції.** Не потрібні MSVC, Rust чи .NET SDK; збирається на будь-якому ПК з Node.js. Агент — один `VadeAgent.exe` (Node single executable application) без залежностей на ігровому ПК.
* **Windows-специфіка робиться штатними засобами**: `reg.exe` (зокрема `reg load` для NTUSER.DAT), NTFS junction через `fs.symlink(..., 'junction')`, `powercfg`, `shutdown`, `taskkill`, Task Scheduler. WinAPI `SetThreadExecutionState` і справжній сон (S3) викликаються через PowerShell `Add-Type` (P/Invoke). Перевірено: це працює навіть з увімкненим Smart App Control (PowerShell лишається у FullLanguage).
* **Electron** — зрілий і передбачуваний на Windows, працює повністю офлайн (жодних CDN, шрифти системні).

Компроміс: `VadeAgent.exe` важить ~96 МБ (усередині рантайм Node 26) і займає ~40–60 МБ RAM у простої.
Для ігрових ПК це прийнятно. Протокол задокументований ([PROTOCOL.md](PROTOCOL.md)), тож агента за потреби
можна переписати на Rust/Go/C#, не чіпаючи адмінку.

## Розклад: дві незалежні гілки

Нічна робота не повинна залежати від одного ПК:

1. **Агент сам запускає завдання** у свій слот (`AgentScheduler`, перевірка годинника кожні 15 с, без довгих таймерів, тож коректно поводиться після сну).
   Слот = `старт + (номер ПК − 1) × крок`, як у `.bat`. Якщо ПК увімкнувся пізніше, завдання все одно виконається в межах `catchUpMin` (30 хв).
2. **Агент реєструє задачу Windows з WakeToRun** (`\VadeAgent\VadeAgent Wake`) на `слот − 2 хв`. Windows програмує RTC-таймер, і ПК прокидається зі сну чи гібернації сам — навіть якщо адмінка вимкнена.
3. **Адмінка шле Wake-on-LAN** за `wolLeadMin` (2 хв) до слоту, якщо ПК не на зв'язку. Повторює кожні 2 хв до `слот + 10 хв` (максимум 4 спроби). Це єдиний спосіб розбудити повністю вимкнений ПК.

Захист від неочікуваного запуску: коли розклад змінюється (або агент отримує його вперше), слот, що вже минув сьогодні,
вважається виконаним. Інакше встановлення агента вдень одразу запустило б обслуговування під гравцем.

## Конвеєр обслуговування (порт `club_night_sleep.bat`)

| Крок | `.bat` | Агент |
|---|---|---|
| Не засинати під час роботи | PowerShell + `SetThreadExecutionState` | те саме; хелпер сам завершується, якщо агент упав |
| Закрити Steam | `taskkill steam / steamwebhelper / gameoverlayui` + 5 с | те саме |
| TEMP | `del /s` по `C:\Users\*\AppData\Local\Temp`, `C:\Windows\Temp` | власне видалення, яке **ніколи не заходить у junction/symlink**; зайняті файли пропускаються |
| Логіни Steam | файли + `reg` по HKU + `reg load NTUSER.DAT` | те саме; тимчасовий hive вивантажується з повторами |
| Кеш, userdata, Майстерня | `rd /s` | те саме + режим «лише вказані AppID» для Майстерні |
| Бібліотеки | розбір `libraryfolders.vdf` через `for /f` | повноцінний парсер VDF (новий і старий формати) |
| Оновлення | junction `C:\steamcmd\steamapps → бібліотека`, `steamcmd +app_update` | те саме; junction видаляється в `finally`, а залишений після збою — при старті агента; справжня папка відсувається, а не видаляється |
| Результат по грі | `findstr` у `last_output.txt` | розбір у реальному часі: OK / Skipped - No subscription / ERROR / LOGIN ERROR, прогрес у % і байтах |
| Після завершення | sleep / hibernate / shutdown, 30–60 с | те саме; сон — справжній S3, а не гібернація (відома пастка `rundll32 SetSuspendState`) |
| Тест без вимкнення | `skip_after.flag` | режим `test` |

## Детектор зайнятості («чи сидить за ПК гравець»)

Агент працює як SYSTEM у сесії 0, звідки не видно ні `GetLastInputInfo`, ні активного вікна гравця. Тому сигнали збирають дві частини:

* **Репортер у сесії гравця** — PowerShell з P/Invoke, який кожні 5 с пише `presence\session-<N>.json`:
  час без миші/клавіатури (`GetLastInputInfo`), чи заблоковано Windows (`OpenInputDesktop` ≠ `Default`), активне вікно (процес, шлях, заголовок)
  і процеси своєї сесії. Запускається задачею `\VadeAgent\VadeAgent Presence` для групи Users (при вході в Windows і повторна перевірка кожні 5 хв,
  завжди один екземпляр) через `conhost --headless`, тож вікно не блимає поверх гри. Папка `presence` — єдина в `ProgramData\VadeAgent`, куди
  можуть писати користувачі (ключ клубу лежить поруч і їм недоступний). У dev/dry-run агент запускає репортер сам як дочірній процес.
* **Агент** кожні 10 с читає свіжий звіт (≤ 30 с). Якщо його немає — бере `tasklist` (~0,3 с) як запасне джерело процесів.

Правила (чиста функція [`evaluateOccupancy`](../apps/agent/src/occupancy/evaluate.ts), покрита тестами), від найсильнішого:

| Сигнал | Результат |
|---|---|
| запущена гра зі списку, або на передньому плані програма з `…\steamapps\common\…` | **Зайнятий** (`game_running`). Ловить і гравців із геймпадом, яких `GetLastInputInfo` не бачить |
| SENET налаштовано: на передньому плані його вікно із заголовком екрана входу | Вільний (`senet_locked`) |
| SENET налаштовано, працює, але екрана входу немає | **Зайнятий** (`senet_session`: клієнт увійшов) |
| Windows заблоковано | Вільний (`windows_locked`) |
| миша/клавіатура активні в межах `idleMinutes` (10 хв) | **Зайнятий** (`active_input`), інакше Вільний (`idle`) |
| звіту з сесії немає: ніхто не увійшов у Windows | Вільний (`no_session`), інакше Невідомо (`no_input_data`) |

Назви процесів і вікон SENET відрізняються між версіями, тому за замовчуванням не задані. Адмін бачить активне вікно ПК у живому лозі
й одним кліком «Це екран входу SENET» додає його в налаштування. Пам'ять ігор не читається; використовуються лише ті ж API, що й у Discord чи
оверлеїв, — без ризику для античитів.

Наслідки:

* **Нічний запуск** (`skipIfOccupied`, увімкнено): якщо в слот ПК зайнятий, агент пише `Skipped: PC is occupied by a player`, **не закриває Steam**
  і перевіряє далі протягом `catchUpMin`. Щойно ПК звільнився — запускає обслуговування; якщо так і не звільнився — пропускає до наступної ночі.
  `unknown` запуск не блокує: зламаний репортер не повинен зупинити всі оновлення (ігри все одно видно через `tasklist`).
* **Ручний запуск**: агент відмовляє з кодом `occupied`; адмінка показує, хто й чим зайнятий, і пропонує «Лише вільні» або «Примусово» (`force: true`).
* **Сайт**: зайнятий і «невідомо» показуються як `occupied` (див. [SITE_INTEGRATION.md](SITE_INTEGRATION.md)).

## Швидке очищення після виходу клієнта

[`PostSessionWatcher`](../apps/agent/src/occupancy/postSession.ts) стежить за переходами детектора. На «зайнятий → вільний» він чекає `delaySec`
(45 с, на випадок, якщо клієнт лише докидає час), і якщо ПК не став знову зайнятим, запускає [`runQuickClean`](../apps/agent/src/jobs/quickClean.ts) (2–3 с):

1. один `taskkill` для `closeApps` і процесів вибраних браузерів;
2. лише дані входу Steam: `loginusers.vdf`, `ssfn*`, `local.vdf`, `AutoLoginUser` / `RememberPassword` у завантажених профілях реєстру;
3. сесії браузерів ([browsers.ts](../apps/agent/src/jobs/browsers.ts)): у кожному профілі Chrome, Edge, Opera/GX (Chromium) видаляються `Cookies`,
   `Network\Cookies`, `Login Data`, `Web Data`, `Local Storage`, `Session Storage`, `Sessions`, `IndexedDB`, `Current/Last Session|Tabs`; у Firefox —
   `cookies.sqlite`, `logins.json`, `sessionstore*`, `storage\default|temporary` (`storage\permanent` з даними розширень лишається).
   Закладки, розширення й налаштування не чіпаються.

Кеш, ігри, Майстерня і SteamCMD не використовуються. Стан «невідомо» таймер скасовує: на невизначених даних нічого не видаляється.
Ручний запуск — кнопка «Очистити логіни зараз» (команда `session.clean`, для зайнятого ПК з підтвердженням).

## Диски

Агент раз на 10 хв отримує список фіксованих дисків (`Win32_LogicalDisk DriveType=3`), а щохвилини читає вільне місце через `statfs`, без запуску процесів.
Статус надсилається, лише коли щось змінилось більше ніж на 512 МБ. Пороги жовтого й червоного (`diskWarnGb` 30, `diskCritGb` 15) задаються в адмінці.

## Оновлення агента по мережі (OTA)

1. Адмінка піднімає HTTP-сервер (порт 7421 або вільний) **лише на час** оновлення і роздає `VadeAgent.exe` за випадковим шляхом.
2. Агентам по автентифікованому каналу йде `agent.selfUpdate { url, sha256, version }`. URL будується з IP адмін-ПК, яким бачить його конкретний агент.
3. Агент стрімить файл у `VadeAgent.new.exe` і рахує sha256; якщо не збігається — файл видаляється і нічого не міняється.
4. Помічник запускається **одноразовою задачею Планувальника від SYSTEM**, а не дочірнім процесом: WinSW при зупинці служби вбиває дерево процесів агента.
   Помічник зупиняє службу, зберігає `VadeAgent.old.exe`, ставить новий файл, стартує службу і чекає маркер `update\started.json` з новою версією.
   Немає маркера за 60 с — відкат на стару версію.
5. Адмінка чекає, поки агент відключиться і повернеться з новою версією (до 3 хв), інакше позначає «відкат» або «не повернувся». Одночасно — до 4 ПК.

Агенти до 0.3 команди `agent.selfUpdate` не мають: перший перехід на 0.3 робиться через `install.cmd`.

## Черга обслуговування (контроль навантаження)

Режим розкладу `queue` замість фіксованого кроку: о `startTime` адмінка будує чергу (спершу зони з `zoneOrder`, далі за номером ПК) і обслуговує
не більше `maxConcurrentUpdates` (3) ПК одночасно. Щойно один ПК завершив, упав або вийшов за таймаут, стартує наступний
([workQueue.ts](../apps/admin/src/main/workQueue.ts), [maintenanceQueue.ts](../apps/admin/src/main/maintenanceQueue.ts)). Вимкнений ПК отримує WoL,
коли настає його черга, і має підключитися за 3 хв. Зайнятий гравцем ПК йде в кінець черги, а якщо й тоді зайнятий — пропускається.
У цьому режимі власний нічний таймер агентів вимикається (інакше обслуговування пройшло б двічі), тож головний ПК має працювати вночі.
Ту саму чергу можна запустити вручну: «Ще → Обслуговування чергою».

## Інтеграція з сайтом

`SitePublisher` у main-процесі адмінки будує публічний пейлоад (`id`, `zone`, `status`) з тих самих даних, що й картки ПК, і шле
його POST-запитом з `Authorization: Bearer`. Запит іде лише при зміні публічного статусу (debounce 2 с) і як heartbeat раз на 10 хв.
Лічильник успішних запитів за добу UTC з лімітом (900) тримає сайт у межах Cloudflare KV Free. Подробиці та приклад Worker —
[SITE_INTEGRATION.md](SITE_INTEGRATION.md).

## Карта клубу

Вкладка «Комп'ютери» за замовчуванням показує карту ([`renderer/map`](../apps/admin/src/renderer/map)), картки лишились як
альтернативний вигляд. Карта — SVG на сітці (24×14 клітинок у стандартній схемі): місце прив'язане до **номера столу**, а не до
запису в `pcs.json`, тож номер без ПК у базі малюється як неактивне місце (клік → «Додати ПК №N»), а перенумерований ПК
переїжджає на місце свого нового номера. Модель і стандартна схема залу — [`shared/mapLayout.ts`](../apps/admin/src/shared/mapLayout.ts)
(спільна для main і renderer), операції редактора — чисті функції в [`mapEdit.ts`](../apps/admin/src/renderer/map/mapEdit.ts), покриті тестами.

Колір іконки ([`mapStatus.ts`](../apps/admin/src/renderer/map/mapStatus.ts)) береться з того самого `deriveDisplayStatus`, що й бейдж картки,
плюс детектор зайнятості: online + вільний — зелений, online + зайнятий — синій, Cleaning/Updating — жовтий з пульсацією
(смужка показує % завантаження SteamCMD), Error — червоний, Sleeping — фіолетовий, Offline — сірий. Крапка в куті — мало місця на диску.
Вибір ПК спільний для карти й карток, тож групові дії верхньої панелі працюють в обох виглядах; фільтр зони й пошук приглушують решту.

## Обліковий запис SteamCMD

Агент працює як SYSTEM, а кешований вхід SteamCMD прив'язаний до облікового запису Windows. Саме тому старий `.bat`
скаржився на `LOGIN ERROR`, коли задача працювала як SYSTEM. Рішення: «Вхід SteamCMD» в адмінці виконує
`steamcmd +login` **від імені агента** на кожному ПК. Пароль іде зашифрованим ключем сесії, не пишеться в лог
(маскується навіть у виводі) і ніде не зберігається. Steam Guard підтримується: код вводиться в тому ж діалозі.

## Безпека

* Ключ клубу живе в `C:\ProgramData\VadeAgent\agent.json`. Інсталятор обмежує права на папку (SYSTEM + Administrators), тож гравець прочитати ключ не може.
* Агент відхиляє `steamPath` / `steamcmdDir`, що вказують на корінь диска або не є абсолютними шляхами.
* У `dry-run` (`--dry-run`) усі дії, що змінюють систему, лише логуються. Саме так агент перевірено на ПК розробника.
* Пакет агента для встановлення містить ключ: не залишайте його на ігрових ПК.
